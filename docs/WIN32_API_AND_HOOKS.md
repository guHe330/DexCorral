# Windows APIs and Hooks Used

As of September 6, 2026. Inventory of the project's own C++ production code in `DexCorral/src`, `DexCorral/include`, and `DexCorral/ShellExtension`.

This document covers directly called Windows functions, dynamically loaded system functions, and the COM calls and SDK macros listed separately below. Project-internal functions, the C/C++ standard library, third-party code, tests, and installer scripts are outside this API inventory. Source links show usage in the project; descriptions explain the purpose of each API or related group. Related functions share a short description.

## Hooks and Event Monitoring

| Mechanism | API / Callback | Short description | Source |
| --- | --- | --- | --- |
| Global mouse hook | `SetWindowsHookExW(WH_MOUSE_LL)`, `MouseHook::MouseProc` | Reports left-button events and mouse movement to application callbacks. Routes mouse-wheel events specifically to `DexCorralWindowClass` and consumes those events; other events continue through `CallNextHookEx`. `Stop` removes the hook. | [MouseHook.cpp](../DexCorral/src/MouseHook.cpp) |
| Explorer startup hook | `SetWindowsHookExW(WH_GETMESSAGE)`, `WakeHookProc` | Temporary hook on Explorer's desktop thread that loads `DexCorralHook.dll` into Explorer. A message wakes the thread; the startup hook is then removed. | [main.cpp](../DexCorral/src/main.cpp), [dllmain.cpp](../DexCorral/ShellExtension/src/dllmain.cpp) |
| Foreground changes | `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)`, `App::WinEventProc` | Observes foreground changes with `WINEVENT_OUTOFCONTEXT` and `WINEVENT_SKIPOWNPROCESS`, causing Corrals to be placed at the bottom of the Z-order again. Removed with `UnhookWinEvent`. | [App.cpp](../DexCorral/src/App.cpp) |
| Explorer rendering | `SetWindowLongPtrW(GWLP_WNDPROC)`, `ShellDefViewSubclassProc` | Subclasses `SHELLDLL_DefView`: suppresses drawing of assigned desktop icons through `NM_CUSTOMDRAW` / `CDRF_SKIPDEFAULT` and handles desktop menu behavior. | [CorralHook.cpp](../DexCorral/ShellExtension/src/CorralHook.cpp) |
| Explorer input and icon positions | `SetWindowLongPtrW(GWLP_WNDPROC)`, `ListViewSubclassProc` | Subclasses `SysListView32`: filters input on hidden icons and handles requests including icon positioning by identity and snapshots. Forwards messages through `CallWindowProcW`. | [CorralHook.cpp](../DexCorral/ShellExtension/src/CorralHook.cpp) |
| Explorer drop target | `GetPropW`, `RevokeDragDrop`, `RegisterDragDrop`, `DropTargetWrapper` | Reads `OleDropTargetInterface` and wraps the existing `IDropTarget`. Blocks drops on hidden icons and forwards other drops to the original target. A timer retries installation and checks registration. The property and Explorer window structure are implementation assumptions of this integration. | [CorralHook.cpp](../DexCorral/ShellExtension/src/CorralHook.cpp) |
| Rename edit control | `SetWindowSubclass`, `EditSubclassProc` | Handles input in the edit control; forwards messages through `DefSubclassProc` and removes the subclass with `RemoveWindowSubclass`. | [CorralWindowDialogs.cpp](../DexCorral/src/CorralWindowDialogs.cpp) |
| Shell changes | `SHChangeNotifyRegister`, `SHChangeNotification_Lock/Unlock` | Subscribes to `SHCNE_UPDATEIMAGE` for updated Shell icons, reads notification data, and unsubscribes during shutdown. This is a Shell notification subscription. | [App.cpp](../DexCorral/src/App.cpp) |
| Directory changes | `ReadDirectoryChangesW`, events and overlapped I/O | Watches the user desktop, public desktop, and virtual folders for file changes using directory notifications. | [DesktopMonitor.cpp](../DexCorral/src/DesktopMonitor.cpp), [FolderWatcher.cpp](../DexCorral/src/FolderWatcher.cpp) |

When removing Explorer subclasses and the drop-target wrapper, the code checks whether DexCorral still owns each registration. Later registrations by other software are preserved. Hook safe mode uses a registry sentinel, and exception handling can skip or disable Explorer hooks; see [CorralHook.cpp](../DexCorral/ShellExtension/src/CorralHook.cpp).

## Maintenance

Update these tables when adding Windows calls or changing hook registration and cleanup. Check dynamic exports resolved through `GetProcAddress` separately: `RtlGetVersion` and `GetDpiForMonitor` are system functions; `WakeHookProc`, `DexCorralRegister`, `DexCorralUnregister`, and `DexCorralCleanupLegacy` are project DLL exports and therefore do not add Windows APIs to the inventory.
